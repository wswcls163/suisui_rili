# 第一版实现与验证记录

日期：2026-09-05。应用在 `mobile/`，旧 `demo/` 继续保留。

## 已实现

- 七列阳历 / 农历月历、月切换、年月日滚轮跳转、回到今天、选中日期事项列表。
- 常见节日、南北小年、二十四节气和三个历史纪念日强调标注，同日多项完整展示；传统节日逐年换算、闰月不重复，除夕和节气动态计算，生日标记仍保留。
- 生日簿、详情、未来三次生日、新建、编辑和确认删除。首次使用为空。
- 累计日新建、列表、首页摘要、详情、编辑和确认删除；开始日为第 1 天，跨午夜自动递增，未来开始日自动倒计时。
- 各处统一生日标题，兼容仅填姓名或已带“生日”后缀的记录，避免重复追加；存储与编辑保留原始输入。
- 一人一条记录支持只过农历、只过阳历、两个都过；独立输入和预览、阳历固定月日、同日合并、平年 2 月 29 日提前到 28 日。
- 原始农历月日和闰月标记持久保存；闰月缺失回退、小月三十提前至二十九，同一农历年只提醒一次。
- 真实北京时间下的当天全部生日提醒，选日和翻月不改变今天；前台跨午夜、恢复前台、返回首页和 CRUD 后刷新。
- 手机 SQLite、电脑 IndexedDB 仓库，读写错误提示、输入保留与重试、事务和更高数据版本保护；v4 迁移保留旧生日并增加累计日。
- 邮箱密码注册、登录、邮箱验证回调、找回密码、保持会话、退出和注销入口；未配置云端时继续本地使用。
- 按访客和账号隔离的本地数据、离线写入队列、首次合并、完整拉取、版本冲突处理、退避重试，以及 Supabase 表、RLS、幂等 RPC 和注销 Edge Function。
- 电脑宽屏与手机宽度布局，共用同一业务逻辑；配置同一 Supabase 项目后使用同一账号同步。

## 电脑浏览器实际操作

在 `http://localhost:8081` 验证了空状态、新增当天生日、提醒和月历同步、刷新后数据保留、详情未来三次换算、编辑到次日后移除当天提醒、生日簿剩余天数、确认删除及清空测试记录。

初次交付时检查了 390 像素手机宽度和 1280 像素电脑宽度，没有页面横向溢出；日期选择器可滚动选择三十天。浏览器验收未出现控制台错误，当次测试记录已删除。浏览器数据只属于当前浏览器和当前访问地址；后续更新保留用户已有记录。

节日功能追加验收：检查了当前九月的教师节、中秋标注，以及 2020 年十月同日中秋与国庆的数量提示和完整名称。390 像素宽度下节日文字、选日标签和农历日期均正常显示，无页面横向溢出；同月已有生日标记仍保留。此次只浏览日期，未修改已有生日记录。

小年、节气与纪念日追加验收：浏览器检查 2026 年二月南北小年、立春和雨水，九月的抗战胜利纪念日、九一八事变、白露和秋分，以及 2017-01-20 北方小年与大寒重合，保留用户已有生日数据。此次重新运行规则、存储、历法、类型、Lint、格式、文档与旧 Demo 测试，以及 Web 和 Android / iOS 资源导出；Expo Doctor 和 Android 原生工程生成沿用依赖及配置未变时已通过的检查。

节日名称显示调整：取消网格简称和长名称缩小字号，使用“国庆节”“中秋节”“九一八事变”“北方小年”等完整名称，放不下时单行尾部省略。更新交互测试覆盖七种名称、统一字号、尾部省略、选日全称及同日数量提示。浏览器实测 390 像素宽度下长名称出现省略号，文字仍为 10 像素且无横向溢出；1280 像素宽度下名称完整展示，选日详情保持全称。测试过程中仅浏览日期，保留原有生日记录。
